## 1. 요청 사례 및 검증 범위

대상 영상은 `Dental_015/example_panorama/panoramic-x-ray-thegem-blog-default.jpg`입니다. 안현찬 치과의사가 제시한 기대 소견은 #18/#28/#48 매복, #18/#28 치관 인접 과잉치, #16/#26/#36/#46 수복물입니다. 이 소견을 이번 단일 영상의 임상 기준으로 전달받아 현재 로컬 API 결과 및 코드 경로와 비교했습니다. 본 문서는 독립적인 임상 판독을 대신하지 않습니다.

첨부된 화면에는 파노라마 영상은 보이나 치식·매복치·수복물 오버레이가 보이지 않습니다. 화면 캡처 시각/실행 커밋은 확인할 수 없어 캡처가 현재 `Dental_015` 코드와 동일한 프런트엔드였다고 단정하지 않았습니다. 현재 저장소는 `Dental_015` `a07e9b8`(오버레이), `Dental_Panoramic_Reader` `7142253`(파이프라인 통합)까지 반영된 상태입니다.

## 3. 원인 분석

### P0 — 매복치 후보 생성과 매복 판정이 분리되어 있지 않음

`Dental_Panoramic_Reader/core/pipeline.py`는 #18/#28/#38/#48 중 `Dental_008`에서 해당 FDI 번호가 존재하기만 하면 모두 `009_impacted`에 추가합니다. 해당 위치에 제3대구치가 있다는 사실만으로 매복으로 확정하는 구조이며, 맹출된 제3대구치를 제외하는 매복 여부 분류/판정 기준이 없습니다. 이 때문에 #38은 결과 내부에서 `Fully Erupted`라고 하면서 동시에 `impactedTeeth` 목록의 매복치로 분류되는 모순이 실제 발생했습니다.

또한 제3대구치 검출 신뢰도나 `uncertain` 플래그를 매복치 포함 조건에 적용하지 않습니다. 이번 실행에서 #18/#28의 치아 검출 신뢰도가 각각 0.22/0.21인데도 매복 분석에 들어갔습니다.

### P0 — Winter 분류 입력이 치아 장축이 아니라 사각형 BBox

파이프라인은 분할 윤곽이 아닌 축 정렬 사각형 BBox의 네 모서리를 합성 윤곽으로 만들어 `Dental_009`에 넣습니다. `Dental_009`는 이 사각형에 PCA를 수행해 치아 장축을 추정합니다. 사각형의 종횡비/기울기만 반영될 수 있으므로 실제 치아 장축 및 인접치와의 관계를 안정적으로 추정하지 못합니다. 제2대구치 BBox가 없으면 각도 0, `Isolated / Impacted`, `Fully Impacted`를 직접 반환하는 경로도 있어 관측되지 않은 정보를 확정값처럼 만듭니다.

이번 실제 출력에서도 #18/#28은 0도에 해당하는 `Vertical`로 보고되었으며, 기존 치아 존재 신호와 맹출 상태 판단이 서로 충돌합니다. 구체적인 매복 방향과 맹출 여부는 현재 기하 휴리스틱 출력으로 확정할 수 없습니다.

### P0 — 우식 신뢰도가 유실되어 전 치아 수준의 큰 박스가 85%로 승격됨

이번 API 재현은 우식 32건을 반환했고, 모두 confidence `0.85`였습니다. 박스 중 일부는 정규화 기준 폭 약 0.13, 높이 약 0.35로 개별 우식 병소라기보다 치아 대부분을 덮는 크기이며 #15와 #42에는 중복 항목도 있습니다. 이는 한 장에서 우식 소견이 많다는 임상 판정이 아니라 데이터 전달·매핑 문제로 보아야 합니다.

`Dental_Panoramic_Reader/core/pipeline.py::_map_lesions_to_fdi`는 `Dental_002` 출력의 `scores`/confidence를 결과에 복사하지 않고 `lesion_type`, `fdi`, `box`만 반환합니다. 이어 `api_server.py`는 빠진 confidence에 기본값 `0.85`를 부여합니다. 즉 모델의 실제 점수가 보고서에서 사라지고 모든 결과가 고정 고신뢰도로 표시됩니다. 병소와 치아 연결도 박스 간 절대 교차면적 최대값만으로 결정하여 중복/경계 사례를 솎지 않습니다. 영상 표면에 박스를 그리는 UI 문제가 아니라 원인상 API 이전의 탐지 후처리/SSOT 매핑 결함입니다.

### P0 — 수복물 결과의 좌표·필드 계약이 생산자와 소비자 사이에서 맞지 않음

`Dental_Panoramic_Reader/modules/restoration_predictor.py`는 검출되면 `fdi`, `restoration_type`, `confidence`를 반환하지만 검출 BBox를 결과에 넣지 않습니다. 반면 `api_server.py`는 `bbox` 또는 `box`를 읽고 없으면 `[0, 0, 0, 0]`을 사용하며, 유형도 `type` 또는 `class_name`만 읽습니다. 따라서 양성 결과가 생겨도 위치는 0 크기 박스가 되고 구체적인 수복물 유형은 일반 `Restoration`으로 떨어져 캔버스 표시가 유효하지 않을 수 있습니다.

추가로 모듈 README는 치아 crop 분류기를 설명하지만 현재 통합 predictor는 YOLO segmentation 모델을 각 치아 BBox crop에 적용합니다. 실제 데이터셋 YAML은 `Caries`, `Crown`, `Filling`, `Implant`, `Root Canal Treatment` 등을 포함하는 31개 클래스 파노라마 객체 검출 데이터입니다. 학습/추론 구조와 입력 단위가 README 설명, 통합 코드 사이에서 일치하는지 확인이 필요합니다. 이번 재현에서 실제 반환값이 빈 배열이므로 그 밖의 수복물 탐지 성능을 이번 한 장만으로 평가할 수는 없지만, API/UI 위치 전달 결함은 코드로 확인됩니다.

### P0 — 과잉치(추가 치아) 표현 자체가 표준 32치열에 묶여 있음

`Dental_008` FDI 보정기는 표준 영구치 32개 순서에 맞춰 번호를 배정합니다. 현재 SSOT 응답 타입에도 `supernumeraryTeeth`와 같은 과잉치 전용 필드가 없습니다. 표준 치열의 번호를 붙이는 모듈만으로 추가 치아를 별도 개체로 탐지·분류하기 어렵고, 과잉치가 있어도 누락되거나 인접 정상 치아의 식별/번호 정렬을 흔들 수 있습니다. #18/#28 인접 과잉치는 독립 객체 탐지와 위치/기준치아 관계를 담는 결과 계약이 필요합니다.

### P1 — 해시 가드는 최신 업로드 연결 문제를 막지만, 캡처 화면 재현을 대신 검증하지 않음

현재 `PanoramaCanvasViewer.tsx`에는 SHA-256 검증 완료 전 오버레이를 보류하고, 불일치·실패·메타데이터 부재 시 차단하는 경로가 있습니다. API는 업로드 원본 바이트의 해시를 반환하고 프런트엔드는 같은 URL을 blob으로 받아 검증 후 표시합니다. 이 가드는 다른 이미지의 리포트를 겹치는 실수를 줄이는 데 도움이 됩니다. 다만 진단 결과가 비어 있거나 잘못 생성되는 문제, #38 오분류, 수복물 누락, 과잉치 미지원은 해결하지 않습니다.

이번에는 API 재현까지 했지만 현재 브라우저 UI를 새로고침해 동일 파일로 재추론하는 엔드투엔드 시각 확인은 수행하지 않았습니다. 따라서 첨부 캡처에서 오버레이가 보이지 않은 직접 원인은 캡처 당시 실행 코드·프런트엔드 번들·리포트 내용이 확보되기 전까지 확정할 수 없습니다. 현재 커밋에서는 캔버스 레이어가 구현되어 있으므로 같은 해시의 최신 API 응답으로 실제 UI를 다시 확인해야 합니다.

### P1 — 전처리 `use_004` 활성화 시 원본 좌표계 변환 누락 가능성

`Dental_004` 구성의 `upscale`은 2이며 초해상도 함수는 결과 영상을 원본의 2배 너비·높이로 반환합니다. 그런데 API는 SSOT 좌표 정규화에 업로드 원본의 `img_w/img_h`를 전달하고 파이프라인에서 초해상도 영상 좌표를 원본 좌표로 역변환하는 처리가 확인되지 않았습니다. `use_004=true`로 추론하면 박스가 밀리거나 경계에서 잘릴 수 있는 좌표계 결함입니다. 이번 재현은 기본 `use_004=false`였으므로 이번 출력 오차의 원인으로 단정하지 않습니다.

## 4. 권고 개선 순서

1. **매복 여부를 단순 존재와 분리:** 제3대구치 식별, 맹출/부분맹출/매복 상태, Winter 방향을 서로 다른 결과로 출력합니다. 매복 상태를 뒷받침하지 못하거나 #008 신뢰도가 낮으면 `uncertain/needs_review`로 남기고 확정 매복 목록에는 넣지 않습니다. `Fully Erupted`와 `impacted=true`가 동시에 반환되지 않도록 스키마 불변조건을 둡니다.
2. **우식 신뢰도와 병소 좌표 보존:** `_map_lesions_to_fdi`에서 원본 score/confidence와 병소 박스를 그대로 전달하고 API는 누락 값을 고정 0.85로 대체하지 않도록 합니다. 치아별 복수 병소·중복 박스·치아 전체에 가까운 비정상 크기를 검증하고, 근거 없는 결과는 표시 대신 검토 대상으로 격리합니다. 치아 귀속은 단순 최대 교차면적뿐 아니라 병소-치아 겹침 비율 및 기준치, 중복 억제 규칙을 명세합니다.
3. **임상 장축 기반 매복 분석:** #18/#28/#38/#48의 분할 마스크 또는 실제 장축 추정값을 사용하고, 박스 네 모서리 PCA를 치아 장축으로 간주하지 않습니다. 인접 #17/#27/#37/#47 미검출은 임의의 Fully Impacted 상태로 바꾸지 말고 분석 불가 사유를 표시합니다.
4. **수복물 생산자/소비자 스키마 통일:** 생산 결과와 타입에 실제 위치 BBox/마스크를 넣고, `restoration_type` 등 유형 필드를 단일 명세로 맞춥니다. BBox가 없는 항목을 `[0,0,0,0]`으로 정상 결과처럼 만들지 말고 API 검증 오류/위치 미상 상태로 격리합니다. 치아 수준 분류만 가능한 모델이면 허위 픽셀 좌표를 만들지 말고 #FDI와 신뢰도만 표시합니다.
5. **수복물 모델 단위와 클래스 재검증:** 학습 데이터의 `data.yaml`, ONNX 모델의 클래스명/출력 형태, 통합 입력이 전체 파노라마 검출인지 개별 치아 분류인지 확인해 하나로 정렬합니다. 실제 정답이 있는 #16/#26/#36/#46을 별도 gold case로 추가합니다.
6. **과잉치 결과 유형 추가:** 표준 32개 치열번호 배정과 별개로 과잉치 객체를 탐지하고, 위치·BBox 또는 마스크·인접 기준치아·신뢰도·불확실성을 기록할 SSOT 타입/API/UI 레이어를 정의합니다. 과잉치를 표준 치아 번호에 억지로 대입하지 않습니다.
7. **초해상도 좌표 변환 보장:** `use_004`의 실제 출력 크기를 메타데이터로 추적하고, 원본 표시를 유지한다면 모든 박스/마스크를 원본 좌표로 역변환합니다. 초해상도 결과를 표시한다면 영상과 좌표 모두 같은 변환 좌표계를 사용하고, 두 모드의 시험 영상을 추가합니다.
8. **화면과 API 결과를 함께 인수:** 같은 원본 SHA-256을 가진 입력에 대해 API JSON과 브라우저 캔버스 픽셀을 대조합니다. API에 `teeth`, `impactedTeeth`, `restorations`, `supernumeraryTeeth`가 있으면 기대한 수·번호·좌표의 오버레이가 보이고, 없는 유형은 누락 상태가 명시되는지 확인합니다. 단순히 “모듈 ONLINE”이나 빌드 성공을 임상 정확도 통과로 기록하지 않습니다.

## 5. 이 영상에 대한 완료 판정 기준
